Claude Playbooks

Unlike the Getting to Know Claude series, these aren't read in sequence. Each one is a self-contained Claude Skill for a specific situation — take the one that matches yours and ignore the rest.

What a "skill" is

A Claude Skill is a text file that tells Claude how to run a specific job — a workflow, a checklist, a way of thinking through a problem — so you don't have to re-explain it every time. Add it once, then just start talking about the thing it's for.

Software development discipline

Six skills that all enforce the same underlying habit: don't claim something works until you've proven it. Written for Claude Code, not general chat — if you're not writing code with Claude, skip this section.

SkillWhat it's forDetails
Test-First Development Tests are written and confirmed failing before any implementation code exists — for every function, endpoint, or module. Always on; doesn't need to be asked for. View skill →
Verification Before Completion Blocks premature "done" claims. Before Claude says something is fixed, working, or passing, it has to run the verification command and show the output first. Evidence before claims, always. View skill →
Testing Practices How to actually set up and write tests — structure, coverage, infrastructure — for whenever the ask is "write tests for this" or "how do I test this." View skill →
End-to-End Feature Test After a feature is built, drives it through the browser like a real user, checks the backend state actually changed, and produces a pass/fail report — not just "the unit tests are green." View skill →
Systematic Debugging Root-cause-first methodology for any bug or test failure — gather evidence, find the pattern, test the hypothesis — before proposing a fix. The discipline that keeps "verify before completion" honest when something's actually broken. View skill →
Code Quality Review A last pass before calling code production-ready — reviewing, auditing, and cleaning up, on top of tests already passing. View skill →

These six are grouped here because they all answer the same question — how do you know it actually works? — not because they're the whole library. The full set, including git and release-discipline skills, is in the Skills Library.
