02 · Applied to a real, half-formed set of requirements

The kind of thing spec-phase's ambiguity scoring is built to catch, worked against an actual draft — an IBKR trading dashboard, requirements written before running GSD at all:

01"Potential profit on existing calls and puts"
Unrealised mark-to-market, or premium captured toward max profit? Different numbers.
02"Max puts sellable without liquidation risk"
The broker's own margin ceiling (what actually triggers liquidation), or a self-imposed cash-secured ceiling the broker doesn't enforce at all? Conflating the two is the single most expensive ambiguity on the list.
03"Capital required to stay safe with broker"
Restating #02, or a genuinely third figure — Maintenance Margin?
04"Income from options, week by week"
Realised only, or does it move with unrealised swings on positions still open?
05"Annualised extrapolation as % return"
Against total account value, or capital actually deployed that week? On this account those two bases moved between roughly 3% and 96% deployed within a single session — the choice changes the answer enormously.
06Google Auth on a single-user localhost tool
Solving a real need (reachable off-machine), or default habit? Exactly the shape discuss-phase is built to redirect to a deferred list rather than silently build.
03 · Against what's already in place here
A lot of this is already running, piecemeal, as global rules — Explore/Plan subagents for research, plan-continuity's docs/handoff/handoff.md for cross-session memory, tdd-first and verification-before-completion always on. The real delta isn't the ideas, it's the enforcement mechanism: GSD wires actual hooks and a CLI around phase transitions, so a gate can be structurally blocked rather than followed by convention. And on code review specifically, this site's own reviewer roster — security-sentinel, architecture-strategist, performance-oracle, the language-specific reviewers — is deeper than GSD's single generic verify step. The honest read: worth running for real on one project, not worth assuming it replaces what's already working.
